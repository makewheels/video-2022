# 已确认需求与范围

本文件记录需求决定。设计中的重试间隔、码率峰值等是实现建议，不能冒充用户亲自指定的数值。

## 功能需求

| 编号 | 要求 | 完成判据 |
|---|---|---|
| R01 | 新云端任务优先自建 CPU/GPU FC，MPS 兜底 | 正常任务不提交 MPS 转码；故障测试证明有限兜底 |
| R02 | 探测、封面也纳入自建方案 | ffprobe 获取源信息，CPU 独立截帧或 GPU 任务顺带截帧；不重复生成 YouTube 已有封面 |
| R03 | 保留本机 FFmpeg/LOCAL | CLI 本地上传不发起 FC/MPS 转码、探测或截帧；LOCAL 服务端登记正常 |
| R04 | 仅 720p/1080p，低清保留原尺寸 | 按设计决策表生成；无独立 480p 档，不放大、无重复档 |
| R05 | 忠实于原片 | 保留帧率、HDR/SDR、颜色表现、画面比例与音轨；不裁剪、降帧、强制单声道或静默转 SDR |
| R06 | 沿用合理的原码率 | 云端以 720p 4 Mbps/1080p 12 Mbps 为起点；峰值受控，实测画质及文件体积；不人为提高低码率原片体积 |
| R07 | 历史不管 | 不历史重转、不删已有播放文件，不批量改历史记录；仍需能播放历史格式 |
| R08 | 有限重试、允许阿里云兜底 | 自建重试耗尽后 MPS 至多一次，不无限循环；兜底同样遵守 R05 |
| R09 | 按需有限并发 | 上限可配置，配额及能力可核对，超出排队，无常驻/预留 GPU |
| R10 | 首轮验证最多 20 元 | 执行前估算、记录花费及保守预留，不把 20 元当成必须花完的金额 |
| R11 | 清理无用北京区 FC 服务 | 完成依赖/任务/调用核查及备份再删，保持仍使用的业务和回滚资源 |
| R12 | 发布统一走 Actions | 镜像、函数配置、服务端切换与回滚均有可追踪的流水线；不得直接改服务器 |

## 需求解释

- “不改内容”指不主动改变原视频的帧率、动态范围、构图、方向、色彩表现和音轨；有损压缩和已确认的分辨率下调会改变像素，不宣称无损。
- 保留 HDR 不代表把 SDR 变成 HDR，也不代表必须生成 HDR/SDR 双份。原片 HDR 输出 HDR，原片 SDR 输出 SDR。
- 低于 720p 的原片作为 720p 档位上限的单档产物登记，实际尺寸必须返回真实值；不得为满足标签而放大。
- 只停止新任务生成其他档位；历史 480p 常量、播放解析和模板若仍被历史业务使用，保留兼容。删除生成分支不等于删除历史文件。
- 本地继续采用本机软件编码，不能要求本地机器有 NVIDIA GPU。HDR 在本地同样不能强制变成 8-bit SDR；本机缺能力必须清楚报错，不自动提交收费云转码。

## 不在本次范围

历史批量迁移、HDR/SDR 双版本点播、4K/2K 新输出档位、播放器功能重做、持续预留 GPU、清理无关云资源。仅为现有端正确播放所必需的协议及播放器适配属于本次范围。
