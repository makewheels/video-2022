# 本轮原型范围与验收

2026-10-10 用户要求开始实施。遵循 PLAN.md 的阶段顺序，先完成独立 Worker 原型，再以 GPU 实测结果决定后端接入。

目标：实现可测试的 FFmpeg HLS 编码、OSS 产物发布和受鉴权保护的任务执行入口。输出沿用现有 `{transcodeId}.m3u8` / `{transcodeId}-%05d.ts`，保持 H.264/AAC 和一任务一档分辨率。

原型内部输入使用现有 jobId/transcodeId/inputKey/outputDir/resolution 语义；bucket、endpoint、回调地址与密钥由部署环境指定。CPU 云函数输入/回调保持原样；不新增用户业务字段、数据库状态或客户端接口。

验收：

1. 单元测试核验参数不通过 shell 执行、长宽比例与不放大、无音轨、产物完整性、OSS 发布顺序、完成后回调及重复提交。
2. 在本地以软件编码生成真实 HLS，ffprobe 验证 H.264、音轨及尺寸，实际读取所有分片；这只证明公共媒体处理流程，不能证明 NVENC 可用。
3. GPU 镜像可构建且能在目标 FC 规格实际执行，OSS 下载/上传及异步调用有证据。
4. 使用相同原片和输出档位对比 MPS 成本/画质/耗时；取得预算与切换门槛后才进入后端接入。

第 3、4 项未通过时不得声称 GPU 可用或开启生产。原型不自动回退 MPS、不做无人值守生产重试；回调失败复用已完整发布的产物重试，不重新编码。
