# Python 后端迁移阿里云 FC：可行性与业务兼容审计

状态：草案，仅交付调查文档；未开始实现、未部署。调查日期：2026-10-14。代码基线：`8e4283e5`。

## 结论

源码盘点未发现某项现有业务从原理上必须依赖常驻业务服务器；Python + FC + MongoDB 路线具备实施条件。但这不是“全部业务已在 FC 跑通”的结论：播放链路 HTTP 适配、数据库网络、长任务资源边界、计费幂等和零空轮询下的任务恢复尚有验证门槛。

**迁移前后业务必须一致。原来用户怎样登录、上传、观看、评论及使用各端，迁移后仍怎样使用；不得通过更改接口、状态含义、播放权限、计费规则或使用流程绕开平台限制。** 用户已经授权的是调研和文档，不是实现或上线。

## 决策边界

- 已确认：阿里云承载业务计算；轻量 Python；无常驻业务实例/保活；本轮继续使用现有 MongoDB，不更换数据库产品或业务数据模型；功能、接口和用户使用方式不变。
- 已确认：首次访问和正常请求响应越快越好，按轻量 Serverless 方式优化；用户未采用建议的冷启动 P95 1 秒/热请求 P95 300ms 数字门槛，不再把指定毫秒值列为待用户选择事项。用真实请求和播放测量验证效果，不承诺平台天然零延迟。
- 技术调查项：Handler/FastAPI、现有 MongoDB 的安全连接路径和跨云延迟、可靠消息/恢复机制由实施方调查和原型选择，不要求用户选择框架或流程。继续使用 MongoDB 不等于授权迁库；若具体方案需要迁位置或新增固定费用，再提交证据和可审阅方案。
- 未来可能评估 TableStore，本轮不做其迁移设计或实现，避免扩大改动量。
- 不纳入本轮：其他同机服务、TableStore 迁移、删除 Java 服务、购买资源、切流和修改线上数据。
- 同机服务不影响本项目方案讨论；MongoDB 若保留腾讯云位置，则属于现阶段明确的跨云例外，不能声称所有存量资源已在阿里云。
