# 需求与迁移兼容要求

状态：草案；仅文档。以本目录 README 的基线为准。

## 1. 目标

后端从常驻 Spring Boot 应用改为按请求/事件执行的 Python 云函数。普通 API 的完全冷启动后首次访问也必须足够快；前端页面不等待业务后端初始化。MongoDB 暂不更换数据模型或数据库产品。

“瞬间”是用户体验目标，不是已经验证的承诺；本轮不擅自把 200ms、500ms 等数值定为用户已批准的标准。原型先提供冷/热请求 P50/P95、最大值、错误率、数据库首连及真实页面可用时间，再据证据确认数值门槛。单次最快结果不能作为验收。

## 2. 不得改变的行为

| 范围 | 兼容要求 |
|---|---|
| 用户及客户端 | Web、console、Android、iOS、CLI、ai-agent 和第三方 OpenAPI 现有调用可用；不要求用户更换操作方式或重新创建数据 |
| HTTP 契约 | 保持方法、路径、参数来源、默认值、必填/可选行为、状态码、业务 code/message、字段类型、空值/缺失、分页/排序、文本响应、跳转及 CORS；不是统一改成 FastAPI 默认 JSON/422 |
| 鉴权 | 保持用户 token、开发者登录 JWT、应用 JWT、OAuth access/refresh/revoke、管理员密钥、回调鉴权及 scope；历史凭据按原有效期继续可用 |
| 上传 | 继续 STS 直传 OSS、原片完成通知、AUTO 去重、LOCAL 不收费云转码、头像和本地封面登记；不把大文件经过 API 中转 |
| 播放 | 保持原域名/链接、`/w?v=`、分享跳转、watchId、主/子 m3u8、302 分片访问、私密权限、签名有效期、清晰度切换和断点/历史；旧 480p/TS、新 fMP4/init/audio 都要覆盖 |
| 媒体与任务 | 保留方向、尺寸、帧率、音轨、HDR 支持边界和失败策略；现有重试/兜底次数、状态语义、历史/在途任务不被清空或重发 |
| 社交与列表 | 评论回复、点赞/踩、订阅、通知未读、列表排序/软删恢复、搜索匹配和可见性规则保持 |
| 财务与统计 | 费用归属、取价时间、精度/舍入、账期、钱包扣款及报表一致；重试不得多扣/漏扣 |
| 数据 | 集合/索引/TTL、字符串 ID 与 BSON ObjectId、日期/时区、Decimal128/BigDecimal、嵌套结构、ID 格式和原子更新逐项核对；不做顺手的数据模型重构 |
| 运维接口 | 版本发布、健康、异常日志、统计、日志补采、开发者文档和管理员访问不遗漏 |

所有限制都以“如何保持现有行为”为前提处理。若必须新增业务字段、调整状态含义、改变同步完成语义或修改接口才能实现，先单列决策；文档中的任务/租约概念不是增加字段的授权。

## 3. 执行约束

- 最小实例数 0，不通过 ping、健康探测、预热保活制造常驻；CPU/GPU 转码函数可继续采用其必要的容器形态，普通 API 不加载媒体依赖。
- 没有访问和待处理任务时不持续空轮询；现有每日业务任务仍会按计划执行并计费，不宣称绝对零调用。
- 一个业务动作只允许一个写入/调度所有者；不得让新旧计费器、重试器、Webhook 派发器同时消费同一工作。
- 先调查 MongoDB 网络，不把腾讯云私网地址当成 FC 可达地址；不在文档存储连接串或凭据。
- 全部部署走现有 GitHub Actions 和取密路径；不得在普通请求中回源旧服务器获取配置、签名或转发业务，否则迁移未完成。
- Java 15 秒 healthy 是历史部署观测，不是 FC 冷启动测量；Python 也有冷启动，不预先保证“零启动时间”。
