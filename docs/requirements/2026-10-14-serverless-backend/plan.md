## P0：契约及数据基线

以 [接口清单](routes.md) 为起点，补齐参数、鉴权/拦截器、状态码、JSON/文本、302、签名和各端调用位置。Controller 声明之外还应录制网关 `/w`、静态前端、console 及框架生成 OpenAPI 文档入口；不得把声明清单称为全部线上可访问路由。

核对 Mongo 部署位置、拓扑、版本、数据量/最大批次、索引/TTL、ID 和金额类型；只读取必要元数据，不输出秘密或用户数据。待授权后取得脱敏兼容样本和备份恢复证明。

产出：逐接口兼容矩阵、媒体样本矩阵、旧服务基线。现有 E2E/Java 测试仅说明有覆盖，不能代替 Python 迁移验证。

## P1：验证先于全面重写

2026-10-14 已开始：`serverless/` 提供两个隔离入口及本地/HTTP 测量工具；现有公开列表字段形状已取得；真实 FC/Mongo 性能和完整业务契约仍待验证。进展及数据见 verification.md，不以该原型表示业务迁移完成。

用代码包原型比较内置 Handler 与 FastAPI Web 函数。至少包括：

1. 空接口，分离平台初始化成本。
2. 真实鉴权 + 视频列表 + Mongo 查询，覆盖首次连接。
3. master/子 m3u8 + `/file/access` 302，覆盖私密权限、签名和实际浏览器首帧。
4. 持久化任务受理、重复投递和恢复，注入写库/发消息间隙崩溃。
5. 香港 YouTube 的真实下载/上传/回调边界，及最大历史 OSS 批次处理。

完全冷启动、已有实例、突发扩容分别测；复用实例不算冷启动。记录函数版本、地域、配置、包大小、网络/客户端、原始样本数，P50/P95/最大值/错误率及费用。独立冷样本不足时明确不宣称 P95。按用户确认的“越快越好”优化，不等待用户指定毫秒数，也不将此前建议值当已批准门槛；不用首页骨架或单次最快请求替代。

本阶段不改变生产域名。若性能不达标，优化依赖和网络；不得用常驻实例、删鉴权/日志/计费或跳过 Mongo 来满足指标。

## P2：兼容实现与离线/隔离验证

未来候选目录为 `serverless/`，最终结构待实施确认；不是本轮新建代码。业务分组按 audit.md 全量覆盖；先认证、读取和播放，再上传与任务控制、社交/列表、开发者/OpenAPI，最后财务/批处理与下载。

- 测试固定输入和旧 Java 可观察输出，跨语言比较；时间戳、随机 ID/签名等通过可控时钟/密钥验证语义，不简单忽略差异。
- Python 写入的 BSON/金额/状态要能被旧 Java 正确读取；敏感数据不进入 golden fixture。
- 补重复/乱序/超时/丢回调/限流/部分失败，金额只能扣一次；批处理半成品可继续。
- 保留现有客户端、CLI LOCAL 和历史媒体访问，无新增业务字段/规则。

## P3：灰度及所有权切换

先只读对比，禁用影子请求隐含副作用；再按可独立回退的业务组切流。签名/回调/状态紧密耦合的转码链路整体选择写入所有者，不逐函数随意拆分。

准备可机器检查的“所有者、在途任务、函数版本、回调地址、调度启停”清单；新旧不可同时生成账单、扣款、派发事件或提交重试。延迟消息及晚到回调跨切换仍按任务身份处理，不能简单丢弃。

如 Mongo 同时需要迁位置，另设先后顺序和单写者窗口；不得在此次灰度中无同步地双写两个 Mongo。域名、VPC、调度等配置按工作区要求记录时间、原因和旧值。

## P4：业务一致验收后退役

Web/console/Android/iOS/CLI/ai-agent/OpenAPI 原流程实际验证，含完全冷启动首次访问、历史视频/新视频/LOCAL/MPS、私密播放和持续播放。确认旧业务服务器无残余配置读取、转发、签名和任务依赖，才安排退役。

回退准备：原 Java 已验证镜像、入口路由及回调配置、原任务状态/幂等记录、数据备份。回退顺序：停止新任务所有者及新调度 → 交接在途/延迟消息 → 路由及回调恢复 → 启用旧所有者 → 原用法冒烟。恢复数据备份不是默认回退手段，以免抹掉迁移后用户写入。
