# 小阶段、多 PR 实施与回退计划

状态：执行中。用户已授权开始，要求小阶段、多 PR，考虑五小时 token 使用窗口及中断接续。原型与生产隔离；业务、接口和用户用法保持一致。

## 执行粒度

- P0–P4是整体里程碑，下表S00–S24保留领域覆盖和历史验收边界；剩余执行以固定M编号交付，不把整个领域或全部迁移做成一个PR。
- 每个任务一个可验证、可回退的交付物；PR包含该交付物必要的旧契约、实现和验收，不再以预计10–30分钟或持续追加字母来拆任务。剩余任务使用固定M编号，内部步骤不再派生新编号。
- 同一时间推进一个实现子阶段；先读相关官方资料，再实现、验证、提交和记录接续。已授权范围内自主继续，不每阶段重新问是否开始。
- 稳定边界及时 commit/push，写入 [progress.md](progress.md)；不推测剩余 token 数，也不等额度耗尽才记任务状态。
- CI 等待不算主动编码时间，不无理由重复全套检查。单阶段未完成时明确半成品和下一条操作；不靠内存或聊天摘要交接。
- 不因限额而删减兼容测试、降低播放/鉴权/计费要求。生产切流、不可逆网络/数据变化或新增需求外规则仍须具体证据与对应授权。

## 每个 PR 的交付要求

1. 阶段 ID、单一问题与实际成果；规划不冒充实现。
2. [官方依据](overview/official-guidance.md)、相关约束、选择理由及未确认能力。
3. 文件范围、原接口/数据语义和公共层依赖边界。
4. 实际命令/CI 链接，明确 passed/skipped/pending/未跑；既有 Java 用例不是 Python 验收。
5. 回退点、在途任务影响和下一阶段，更新 [接续记录](progress.md)。

分支名不含`/`。同一领域按固定M编号交付，不再追加a/b子号；范围明确且共享设施的小任务可合批，逐项保留验收，不遗漏能力或跨阶段一次性塞入大PR。进度和估时按已验交付及实际用时修正，记录阻塞/等待，不用任务数、PR数或测试数换算工作量。早期“1–3天”以及后续周级预算都不是实测工期或绕过验证的理由。

## Git、部署与数据边界

Git 是唯一自研源码来源。流程为已知提交→CI 测试/构建→OSS 不可变产物→FC 版本→别名/入口。不得在 OSS/控制台保留无 Git 来源的正式脚本或在线改函数；回退也从已验证提交/产物执行。

第三方依赖以锁文件/摘要声明，不要求把安装缓存提交 Git。环境差异由 Git 管理的部署声明与取密注入实现，不复制两份业务源码；不能让环境参数选择任意未审核脚本。

公共业务不导入 FC/OSS SDK、框架或 Mongo 类型；云/数据库替换限于适配器和装配，见 [候选设计](../../design/serverless-backend.md)。本轮不实现第二云或 PostgreSQL，也不声称换库零成本。

保持旧 Java 读取新写数据，原片/历史不重转；不默认迁 Mongo 位置。计费、任务重试、Webhook 新旧不能双所有者；平台别名回退不是完整的在途任务交接。
