# 当前设计文档

`docs/design/` 描述系统当前如何工作，是随代码持续更新的 living documentation。

- 需求目标、范围和验收标准放在 `docs/requirements/`；
- 当前架构、数据格式和运行边界放在 `docs/design/`；
- 实施过程和完成证据放在对应需求目录的 `plan.md` 与 `verification.md`；
- 已完成的时间线只写入 `docs/CHANGELOG.md`。

设计变化时直接更新这里的当前事实。重大且难以逆转的设计决策应另建 ADR，以保留当时的选择理由；普通演进由 Git 历史追踪。
