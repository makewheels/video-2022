# Video Agent 评测体系当前设计

> 状态：living document

## 目标与边界

评测体系同时检查单轮能力、工具轨迹、写安全、最终状态和多轮会话。Langfuse 用于保存 Dataset Run、trace 和 score；Git 中的数据文件是版本化事实源。

评测不假设用户始终目标明确。天气等产品能力外请求、查询自己与他人视频之间的切换、忽略回答、重复提问、相对指代、改口和确认串线，属于后续 `session-chaos` 套件的正式覆盖范围。此类请求的正确行为由能力边界和安全不变量定义，不要求唯一措辞或唯一工具轨迹。

## 数据分层

- `smoke-v1`：少量关键读取与 P0 写安全门槛；
- `regression-v1`：当前原子能力回归；
- `multi-turn-v1`：确认、取消和消歧等高风险多轮 Pilot；
- `session-chaos-v1`：规划中，覆盖混合目标、跨域请求、重复表达、长上下文和状态过期；
- 生产 bad case：规划中，只接收经过脱敏与人工确认的真实失败模式。

## 文件格式

供人审阅和 Git diff 的 Dataset、来源登记及旧 seed 使用缩进的 JSON 数组（`.json`）。加载器仍兼容旧 `.jsonl`，便于读取历史或外部流式数据，但新评测资产不再使用 JSONL。

稳定性由用例 `id` 保证；文件从 JSONL 迁移到 JSON 不改变 Langfuse Dataset item 的稳定 UUID，也不改变已有 Run。

## 评分层级

- 单轮：意图、对象、所有权、工具、参数和回答事实；
- 状态迁移：上下文继承、目标切换、确认绑定、取消与重复操作；
- 会话：最终状态、无意外副作用、恢复能力、循环、延迟与成本。

确定性 grader 负责事实、工具、安全和状态，LLM Judge 只补充相关性、清晰度等主观维度，不能推翻安全 veto。
