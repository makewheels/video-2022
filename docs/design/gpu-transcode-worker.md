# GPU 转码 Worker 原型设计

对应需求：[GPU 云函数自建转码](../requirements/2026-10-gpu-cloudfunction-transcode/README.md)。状态：原型，未接入生产。

## 执行与产物

独立 Python Worker，提供本地媒体检查命令和用于 FC 自定义容器的 HTTP 入口。一个请求执行一档转码，进程不自行返回后开启后台线程；异步排队应由 FC 负责，具体 FC 调用适配须云端验证。

请求只接收 jobId、transcodeId、inputKey、outputDir、resolution（720p/1080p）。部署配置固定 OSS bucket/endpoint 和可信回调 URL，避免把私有凭证、任意回调地址放进任务载荷。调用 secret 和 callback secret 使用不同环境变量；HTTP 入口拒绝未鉴权调用。

FFmpeg 以参数数组执行，GPU 使用 h264_nvenc，测试可显式选择 libx264。先用软件解码/缩放验证兼容性，硬解码/缩放作为后续实测优化。尺寸按对应档位的横屏/竖屏边界等比例缩小、不放大并取偶数；音频可选，存在时编码 AAC。初始码率参数仅作原型样本基线，未宣称达到生产画质门槛。

本地每任务使用系统临时目录并 finally 清理；超时终止 FFmpeg。HLS 生成后核验 ENDLIST、片段文件存在及有效时长。OSS 先上传全部 ts，再上传 m3u8；列表存在时重新核验全部引用片段，再复用完成产物发送回调，不重复编码。

## 幂等与边界

进程内互斥防止同实例并发编码；不同实例之间的任务去重需依赖 FC 异步任务唯一 ID 或后续持久化协调，不假设进程锁足以保护生产。首轮云端原型限制单实例单并发，严禁自动并发重试同一任务。

原型完成回调发送 jobId 并携带 X-Callback-Secret，回调目标必须配置为测试接收端；现有 CPU 回调不能识别 GPU provider，不得指向生产 CPU 回调。失败不发送成功回调，调用返回失败供 FC 记录；不新增应用任务状态或自动 MPS 回退。

后端接入要另行补齐任务持久化、独立 GPU 回调、原子幂等登记、失败恢复和在途回滚设计，通过 PLAN.md 门槛后才能进入生产。
